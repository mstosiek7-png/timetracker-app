## 3. Usuwanie budów — fix (`app/site/[id].tsx` + `hooks/useBaustellen.ts`)

### Problem
Ekran `app/site/[id].tsx` miał własną mutację delete która po sukcesie inavlidowała tylko klucz `['construction-sites']`, nie `['baustellen']` — dlatego lista budów (oparta na `['baustellen']`) nie odświeżała się.

### Rozwiązanie
**`app/site/[id].tsx`** — po usunięciu:
```typescript
queryClient.setQueryData(['baustellen'], (old: any[] | undefined) =>
  old ? old.filter((s: any) => s.id !== siteId) : old
);
router.back(); // od razu wraca, bez popupa "Sukces"
```

**`hooks/useBaustellen.ts`** — `deleteSiteMutation.onSuccess`:
```typescript
queryClient.setQueryData(['baustellen'], (oldData: Site[] | undefined) => {
  if (!oldData) return oldData;
  return oldData.filter(s => s.id !== id);
});
```

### Kluczowa lekcja
`invalidateQueries()` tylko oznacza dane jako "stale" — nie usuwa ich z cache natychmiast.
`setQueryData()` aktualizuje cache **natychmiastowo**, co daje natychmiastową aktualizację UI.
